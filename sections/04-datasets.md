# Dataset Generation

This page documents the datasets used in the empirical evaluation of the EAD-API framework. Dataset size plays a central role in exposing the energy impact of API design choices, and was therefore treated as an explicit experimental factor.

---

## Overview

Two dataset configurations were used in the study:

- **Small dataset:** Default Spring PetClinic dataset (approximately 10 owners)
- **Medium dataset:** Scaled dataset containing 1,000 owners

All other experimental parameters (workload rate, deployment configuration, and measurement procedure) were held constant across dataset configurations.

---

## Small Dataset (Default PetClinic)

The small dataset corresponds to the default data provided by the Spring PetClinic REST application.

### Characteristics

- Approximately 10 owners
- Limited number of pets and visits
- Entire dataset easily fits in memory
- Minimal database access overhead

### Purpose in the Study

The small dataset serves as a **baseline configuration** in which fixed costs dominate execution. Under this configuration, the effects of certain API design dimensions (e.g., data access optimizations) are expected to be minimal or difficult to observe.

---

## Medium Dataset (1,000 Owners)

To study how API design choices scale with data volume, a medium-sized dataset was generated by programmatically replicating the owner–pet–visit structure of the default dataset.

### Characteristics

- 1,000 owners
- Each owner associated with pets and visits consistent with the PetClinic schema
- Preserves referential integrity across all tables
- Uses the same database schema and indices as the default dataset

### Generation Strategy

The dataset was generated using SQL scripts that:

1. Truncate existing domain tables while preserving schema structure.
2. Insert owner records with unique identifiers and realistic attribute values.
3. Insert associated pets and visits linked via foreign keys.
4. Preserve indexing and constraints defined by the PetClinic schema.

The generation process avoids synthetic workload artifacts such as skewed identifiers or unrealistic relationships.

---

## Database Schema

All datasets conform to the standard Spring PetClinic relational schema, including the following tables:

- `owners`
- `pets`
- `visits`
- `types`
- `vets`
- `specialties`
- `vet_specialties`

No schema changes were introduced as part of dataset scaling.

---

## Dataset Selection Rationale

Using two dataset sizes enables comparison between:

- **Low-volume scenarios**, where execution overheads dominate and energy differences are small.
- **Higher-volume scenarios**, where response size, serialization cost, and data access patterns scale with dataset size.

This design supports the evaluation of context-dependent effects emphasized by the EAD-API framework.

---

## Reproducibility Notes

The SQL scripts used to generate the medium dataset are included in the companion repository. Users can recreate the datasets by executing the provided scripts against a PostgreSQL instance configured with the PetClinic schema.

Exact instructions for dataset setup are provided in the Replication Guide.
